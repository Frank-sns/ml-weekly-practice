# 第六周：变压器油温预测与序列窗口

使用真实设备数据 ETTh1，完成**根据过去 24 小时的油温，预测下一小时油温**的任务。
本周两个实践：①把连续序列变成窗口样本（L=3 / L=5 对照）；②比较三种预测基线并完成一轮 Ridge 调参与泛化检查。

## 数据来源

- ETTh1.csv 来自 [ETDataset 官方仓库](https://github.com/zhouhaoyi/ETDataset) 的 `ETT-small/ETTh1.csv`，共 17,420 条小时记录（2016-07-01 00:00 ~ 2018-06-26 19:00）。
- 本周只使用**前 14,400 小时**（2016-07-01 00:00 ~ 2018-02-20 23:00）。字段：`date`（记录时间）、`OT`（变压器油温，预测目标）、`HUFL` 等六种负载（本周只用 `HUFL` 做事后作图，不输入模型）。

## 环境与运行

- Python 版本：**3.14.5**
- 安装依赖：

```bash
pip install -r requirements.txt
```

```bash
python run_windows.py      # 实践一：窗口构造演示（L=3 与 L=5 对照）
python run_baselines.py    # 实践二：基线比较 + Ridge 调参 + 泛化检查
```

## 固定设置

- 窗口长度 **L=24**（过去 24 小时预测下一小时），目标始终是"紧接着的下一小时"。
- 划分按**目标时刻**（左闭右开）：训练 `[2016-07-01, 2017-06-26)`、验证 `[2017-06-26, 2017-10-24)`、测试 `[2017-10-24, 2018-02-21)`，样本数 8616 / 2880 / 2880，无重复、无遗漏。
- 先在整个序列上构造窗口、再按目标时间归类：跨边界样本（如第一条验证目标 2017-06-26 00:00）的历史来自边界之前一天，保证输入完整。
- 线性模型统一使用 `StandardScaler + 模型` 管道，**只在训练窗口上 fit**，验证/测试沿用训练统计量；目标油温保持原始尺度。
- 评价场景为"每小时预测一次下一小时"：预测 t 时刻时，可用信息是 t-1 及更早的真实油温。例如预测 2017-10-24 01:00 时，可以使用当天 00:00 的真实油温。

## 窗口修改检查（实践一）

前 12 小时（2016-07-01 00:00~11:00）上，`make_windows` 的结果：

- **L=3**：样本数 = 12 − 3 = **9**。第一条：输入 00:00~02:00（下标 0~2，值 30.531/27.787/27.787），目标 03:00（下标 3，值 25.044）。最后一条：输入 08:00~10:00，目标 11:00。
- **L=5**：样本数 = 12 − 5 = **7**。第一条：输入 00:00~04:00，目标 05:00；最后一条：输入 06:00~10:00，目标 11:00。

结论：窗口越长，可构造样本越少（**样本数 = N − L**）；输入覆盖时长随 L 增长；最近一个输入与目标始终相隔 1 小时（预测步长不变）。两组的最后一条样本目标都是 11:00，但输入起点不同。

## 调参路线与候选选择

选择 **Ridge 路线**（候选 alpha = 0.1、1.0、10.0，覆盖弱/中/强三种正则强度）。理由：滞后特征之间高度相关（相邻小时油温几乎相同），普通线性回归的权重可能对噪声敏感；第三周已经学过 Ridge，alpha 语义直观（越大约束越强），便于结合训练/验证误差判断过拟合。

结果（RMSE，原始油温尺度）：

| 配置 | 训练 RMSE | 验证 RMSE | rmse_gap |
|---|---|---|---|
| lag_linear（参照） | 1.043 | 0.910 | −0.133 |
| Ridge α=0.1 | 1.043 | 0.910 | −0.133 |
| Ridge α=1.0（**选定**） | 1.043 | 0.910 | −0.133 |
| Ridge α=10 | 1.046 | 0.912 | −0.134 |

按验证 RMSE 选定 **α=1.0**（α=0.1 与 1.0 结果几乎完全相同，α=10 略差）。
**过拟合判断**：没有过拟合迹象——三个候选的验证 RMSE 都**低于**训练 RMSE（gap 为负），说明验证时段并没有比训练时段更难；α 增大后训练、验证误差几乎不动，正则化在这份数据上几乎没有发挥作用，模型容量（24 个线性权重）相对数据量（8616 条）已经很小。
**季节/工况解释**：训练段油温标准差 9.19（含两个夏天、波动剧烈），验证段 4.97，测试段只有 3.15（冬季，范围 −3.7~14.8）。因此**测试 RMSE 显著低于验证 RMSE**（如 lag_linear：0.585 vs 0.910）主要来自时段本身的波动差异，而不是模型变好。现有证据足以说明"未见过拟合"；若要更严格，可再按季节分段评价或做滚动验证。

## 最终四种方法

| 方法 | 验证 RMSE | 测试 RMSE | 说明 |
|---|---|---|---|
| last_value | 0.925 | 0.593 | 最近观测，不学参数 |
| window_mean | 1.880 | 1.342 | 24 小时均值，最平滑但最差 |
| lag_linear（**selected**） | 0.910 | 0.585 | 学 24 个历史位置权重 |
| ridge_tuned（α=1.0） | 0.910 | 0.584 | 与 lag_linear 基本持平 |

按验证 RMSE 选出的总体最优是 **lag_linear**（与 ridge_tuned 相同到三位小数，按固定顺序先取 lag_linear）。窗口均值明显最差：油温有很强的日内周期，24 小时均值把峰值和谷值互相抵消。逐条预测已保存，并用 `predictions.csv` 重新计算指标与汇总表核对**全部一致**。

## 观察—预测—解释（验证首周，2017-06-28 00:00~08:00）

- **观察**：00:00~05:00 油温稳定在 20.0~20.8；06:00 小幅回升到 20.68，07:00 回落到 19.77，08:00 继续到 19.42。同一时段 HUFL 从 12 左右在 07:00 骤降到 8.44、08:00 降到 3.95。
- **预测**：06:00 四种方法都预测 20.0~20.1，低于真实的 20.68——这次回升在历史里没有先兆，只靠油温历史看不到；07:00 last_value 预测 20.68（直接沿用上一小时）偏高，window_mean 20.99 最高（24 小时窗口里混着前一天更高的值），lag_linear/ridge_tuned 20.79 居中。
- **解释**：HUFL 大幅下降与油温随后回落的方向相容（负载降低 → 发热减少 → 油温经过热惯性滞后响应），但同向变化只是线索，本模型只读油温、并不知道负载要下降；06:00 的回升也没有任何方法能提前看到。另外本周首周 OT 与 HUFL 的相关系数仅约 −0.28，说明两者的对应关系并不强，未观测的冷却、环境温度等因素也可能在起作用。

## 其他主要发现

- 数据完整性检查全部通过：时间严格递增、无重复、相邻差 1 小时、无缺失。
- 线性模型的 24 个权重是从数据里统计拟合出来的，只反映"历史油温到下一小时油温"的统计关系，不等于设备的物理传热参数。
